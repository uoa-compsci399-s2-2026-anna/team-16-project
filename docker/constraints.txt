# Frozen runtime dependency set. Passed to pip with --constraint in both
# docker/api.Dockerfile and docker/admin.Dockerfile.
#
# WHY THIS FILE EXISTS
#
# pyproject.toml states every dependency as a `>=` FLOOR and there is no
# lockfile anywhere in the tree. Without this file, `docker build` resolves
# each floor to whatever is newest on PyPI on the day it runs - so the image
# verified in the task 2 report and the image the client builds in six months
# are different software, and a FastAPI, Starlette or SQLAdmin major bump
# lands in the deliverable with no signal at all. The bases are pinned by
# digest in the Dockerfiles for the same reason.
#
# THIS IS A CONSTRAINT FILE, NOT A REQUIREMENTS FILE. It does not install
# anything and it does not add a dependency. It only says "if you install this
# package, install exactly this version", so pyproject.toml remains the single
# statement of WHAT is required and this file fixes WHICH VERSION was tested.
# A dependency that stops being required simply stops being consulted here.
#
# HOW TO REFRESH IT, when a dependency is deliberately moved:
#
#   docker compose -f docker/compose.yaml build --no-cache api
#   docker run --rm --entrypoint pip kaicalc-api:local freeze #       | grep -v '^kaicalc @' | sort > docker/constraints.txt
#   (then re-add this header, rebuild from down -v, and re-run the task 2
#    verification - at minimum POST /api/v1/calculate against
#    tests/golden/case_01_canonical_two_entry/expected.json)
#
# `kaicalc` itself is deliberately absent: it is installed from the locally
# built wheel, and a constraint naming a file:// path would break every build
# on every other machine.
#
# Frozen from the build verified in
# .superpowers/sdd/2026-08-10-packaging-and-ci/task-2-report.md, on
# python:3.11-slim / linux/amd64. These are the versions whose calculate
# response matched the golden suite byte for byte.
#
# Refreshed when the PDF export landed: weasyprint and its own dependency
# tree (pydyf, tinycss2, cssselect2, tinyhtml5, fonttools, pillow, pyphen,
# brotli, zopfli, webencodings) are new here. They are pinned for the same
# reason everything else is - pyproject.toml states `weasyprint>=62` and,
# unconstrained, a build in six months would resolve a different layout
# engine than the one whose output was verified. Taken from
# `pip freeze` inside the built image, per the refresh recipe above.
