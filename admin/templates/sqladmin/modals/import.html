{# The import dialog: drag-and-drop, both file formats, and a preview that has to be confirmed before anything is written. THIS FILE REPLACES SQLADMIN'S OWN MODAL RATHER THAN INCLUDING IT, AND THAT IS A CHANGE FROM WHAT STOOD HERE. Until WP4 this template was `{% include "sqladmin_original/modals/import.html" %}` plus three patches around it, on the rule this project follows everywhere else: reach a template, do not fork it. The rule has not changed and neither has the reason — a copied template is somebody else's code that rots silently at the next upgrade — but three of the things this dialog has to do cannot be reached from outside the markup: * **the CSRF token has to be in the request.** sqladmin's own `statics/js/main.js` builds the upload's `FormData` by hand and never serialises the form, so a hidden `` inside its form is in the DOM and in no request. WP1 carried the field past that by replacing `window.fetch` for the duration of one call. It said this modal's replacement would delete that wrapper, and it does: /admin/static/import.js builds its own body and puts the token in it, which is what every other form in this panel does. * **both formats in one dialog.** The shipped input is `accept="text/csv"` and the shipped heading says "Import CSV". This screen takes `.csv` and `.json` on one path (admin/importing.py). * **drag-and-drop.** `dragover`, `drop` and `dragenter` appear zero times in what sqladmin ships; it is a plain ``. NOTHING OF SQLADMIN'S IS COPIED HERE. This is not a fork of that file — it is different markup for a different dialog, and every line of `sqladmin/_import.py` (619 of them: the CSV parsing, the per-row validation, the count check, the streaming response) still runs on the server exactly as before. What changed is the browser half, which is the half sqladmin could not know this panel's rules about. THE OUTER `id="modal-import"` IS KEPT deliberately. sqladmin's own list page renders the Import button with `data-bs-target="#modal-import"`, so keeping the id means the button still opens this dialog without the list template being touched. sqladmin's `main.js` also binds a few handlers at `#modal-import-form`, `#modal-import-text` and `#modal-import-progress` — none of which exist below, so jQuery matches an empty set and they do nothing. That is the point: its submit handler never fires, because there is no `#modal-import-form` for it to fire on. THIS DIALOG RENDERS ONLY WHERE `can_import` IS TRUE, which on this panel is an administrator on one of the fourteen importable screens — seven taxonomy, the five children of a factor set, and the two comparison- scenario tables (admin/importing.py, contract §8.1.1). #}
